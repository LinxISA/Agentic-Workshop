## Keep three different problems separate

1. **Structured sparse matrix compute:** a supported sparsity pattern and metadata drive a matrix engine; this does not imply arbitrary indexed memory or general vector atomics.
2. **Unstructured indexed memory:** gather/scatter requires index preparation, legal address/mask handling, locality and memory transactions. Tile-local rearrangement is distinct from GM/HBM access.
3. **Collision-sensitive updates:** ordinary scatter overwrite, atomic RMW returning an old value, and no-return atomic reduction have different semantics. Histogram construction also differs from scanning an already constructed histogram. Duplicate-address policy, dtype/width, scope/order and faults must be stated.

Sparse/dense workload prevalence remains workload-dependent. The spoken workload names remain unresolved; do not turn them into established algorithms or universal hardware requirements.

## Our pinned-boundary review

The reviewed checkouts remain Linx API `fac242a95bc70cd1783547555e5bd7335d1969bf`, Bench `349c98964144dfd9ca6a2665eca5a16ca8f3e045` and TimingSim `d5419b3e721df47daae02c38ef2a9b82187e5149`. The pto-spec checkout has an unfinished merge; only committed HEAD `a292fab1c852e87308da87cbbe181c6bc2cd263c` was used. Their contracts must not be silently combined.

- **Historical snapshot addressing mismatch (superseded by the candidate review above).** The pinned ASL `TileMemoryIndexedStridedAddress` treats signed/unsigned index as a logical linear element, maps row/column, applies row stride and multiplies by element bytes. Some generated reader prose instead says byte displacement; the normative ASL owns this revision. Bench ordinary gather/scatter explicitly multiplies indices by `sizeof(D)`, and the inspected model AGU reads32-bit indices and computes base+index bytes. The atomic API also names logical element indices, while Bench top-k inline assembly multiplies bins by4. Resolve target revision/build/address contract before using any sequence as a correctness example.
- **Mask and subbyte scope:** pinned indexed transfer accepts integer index types but rejects packed4-bit transfers without a nibble selector. Mask contracts use canonical U8 predicates. Current frontend supports constrained masked gather, rejects CUBE mask carriers through its validation path and explicitly rejects masked scatter. Ordinary scatter duplicate writes are not atomic reduction; pinned ASL gives implementation-defined duplicate winners. [Pinned scatter semantics](https://github.com/PTO-ISA/pto-spec/blob/a292fab1c852e87308da87cbbe181c6bc2cd263c/asl/tile/model/memory/gather-scatter.asl#L74).
- **Atomic API is finite:** add wrappers allow FP16/BF16/FP32/FP64/S32/U32/U64; min/max allow S32/S64/U32/U64. Index types are S32/U32/S64/U64 with shape/layout matching. Gather-family RMW publishes observed old values; scatter-family reduction has no return Tile. CAS has explicit expected/replacement operands and U16/U32/U64 transfer legality. This does not establish unlimited vector atomic types, masking, concurrency, faults or implementation throughput.
- **Current model coverage:** the inspected TLSU frontend/L2 bus routes TLOAD, ordinary MGATHER, constrained MGATHER_MASK, TSTORE and ordinary MSCATTER; the bus has no atomic-add/min/max/CAS request kind. AGU coalesces requests within cacheline×return-beat keys and bounds pending requests; scattered locality can still multiply requests. General atomic execution is not established by API wrappers or legacy enum names. These are source observations, not a runtime verdict across other engines.
- **Actual Bench evidence:** [ordinary gather/scatter and CAS templates](https://github.com/PTO-ISA/SuperNPUBench/blob/349c98964144dfd9ca6a2665eca5a16ca8f3e045/microbenchmark/memory/memory_bench.hpp#L47) pay explicit index loads, data/mask loads and output stores. ## Historical local snapshot: how the ordinary indexed GM path works

At the previously inspected local snapshot, the ordinary path is `MGATHER(dst, global_tensor, offsetTile)` or `MSCATTER(global_tensor, dataTile, offsetTile)`, emitted as `BSTART.TLSU MGATHER/MSCATTER` plus typed geometry, Tile bindings and GM base/stride GPR bindings. This is GM memory access, distinct from TEPL `TGATHER/TSCATTER` within Tiles. [Gather emitter](https://github.com/LinxISA/Linx-TileOP-API/blob/fac242a95bc70cd1783547555e5bd7335d1969bf/include/jcore/template_asm.hpp#L865), [scatter emitter](https://github.com/LinxISA/Linx-TileOP-API/blob/fac242a95bc70cd1783547555e5bd7335d1969bf/include/jcore/template_asm.hpp#L958).

1. **Prepare offsets:** the sampled Bench loads an S32 index array into a Tile before issuing indexed access; its test cases multiply logical indices by `sizeof(D)`. Arithmetic-produced offsets are also present in the top-k example. Offset traffic/readiness is real work; the API does not synthesize arbitrary index arrays for free.
2. **Read operands:** indexed command binding supplies the index-Tile physical address, data-Tile address for scatter and destination-Tile address for gather. InstBuffer reads scatter payload; AGU reads indices through the RWDB Tile-read queue in bounded beats. The inspected default beat is128B, so a full index beat carries32 four-byte indices; cacheline default is256B. These are configurable model/default sizes, not guaranteed production hardware.
3. **Form addresses:** current AGU decodes each index as a zero-extended32-bit quantity and computes `gm_base + index` in bytes. It does not implement the pinned ASL's signed/unsigned32/64-bit logical-element-plus-row-stride formula. API-emitted stride is therefore not evidence of strided element interpretation in this current AGU path. Data elements are asserted not to cross a cacheline; broad signed/64-bit, subbyte or arbitrary shape support is not established.
4. **Build/coalesce requests:** within one returned index-read beat, gather groups elements by `(GM cacheline, destination return beat)` and records source-byte offset, destination-byte offset, byte count and return-beat identity. Scatter groups by GM cacheline and composes line-sized data plus byte write masks. This is a limited coalescing window, not whole-Tile/cross-instruction deduplication; a poor address distribution still creates many requests. A destination beat can depend on multiple index beats and multiple cachelines.
5. **Queue and return:** bounded pending TagReqs and AGU ingress/send-width grants apply backpressure. Tag lookup and BYPQ/MROB/data-slot admission route hits, in-flight-line waits and misses. On load return, MROB/BYPQ hand a cacheline snapshot to RWDB; RWDB copies mapped byte ranges into a destination-beat buffer, tracks filled bytes and completion, then publishes Tile data/readiness. Logical output order is reconstructed by maps rather than requiring memory replies to arrive in element order.
6. **Scatter collision/order:** within the same index-read beat, repeated destination bytes are overwritten by later local-loop iterations in the assembled write buffer. This implementation observation is not a guaranteed global duplicate winner across beats/PEs or an atomic-add contract. The frontend conservatively treats an indexed store's unknown footprint as potentially aliasing within its checked ordering domain. Memory scope/attributes and cross-agent outcomes must still follow the applicable contract; no unlimited vector-atomic support is inferred.

Required costs include index/data/mask Tile reads, address/map construction, line/beat request multiplicity, tag and queue admission, data/return buffers and byte assembly. This source review explains mechanisms; it neither validates every representation nor measures locality/coalescing benefit.

## Comparison boundary and next evidence

Use one named workload and matched semantics: index width/units, data type, mask density, locality, duplicate distribution, contention across lanes/threads/cores, fault/order/scope and output requirements. Compare direct indexed updates with optimized deduplication, local/private accumulation, sorting/segmentation and explicit merge. Account for index/mask traffic, routing/transactions, banks/cachelines, scratch/buffers/registers, preprocessing, synchronization and atomic serialization. Dynamic scheduling may overlap eligible requests; it cannot remove representation, locality or correctness obligations. No architecture or PPA/performance winner is established.
